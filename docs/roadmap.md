# 交付路线与验收门槛

> 状态：待实施路线。此文不是完成清单；网页前端已改为 Daymark 三页工作台，服务端仍以旧浏览器语音恢复原型为主。任务按依赖排序，暂不虚构完成日期或全平台可用承诺。

## 1. 建议的 PR 顺序

每个 PR 只完成可独立检查的增量，说明问题、改变后的行为、迁移方式和验证证据。

| 顺序 | 交付范围 | 合入门槛 |
|---|---|---|
| PR 1：契约与边界 | 在旧 Zod 契约旁新增采集、任务、事件、证据、覆盖和错误契约；定义存储与处理器接口 | 合法／非法输入及版本兼容用例；旧客户端仍可使用原接口；明确哪些文件只有定义 |
| PR 2：可靠接收 | 本地持久化、原始文件存储、幂等写入、任务队列、接收确认、可恢复上传；修复握手与连接生命周期 | 确认前后崩溃、重放、乱序和断线重启验证；已确认记录不丢、不重复，缺口被报告 |
| PR 3：整理管线 | 接入现有 ASR 适配器，新增 OCR、截图去重、时间对齐、事件与来源关系；处理版本和重试 | 同素材重跑无重复事实，失败可重试，临时／最终转写不叠加，修正结果可重建索引 |
| PR 4：检索服务 | 时间／来源过滤、全文检索、可选语义索引；实现 `search`、`get_event`、`get_source`、`get_coverage` 的 HTTP／MCP 适配 | 通过证据检索样本集；权限与删除检查覆盖四个工具；空结果与离线／未处理明确区分 |
| PR 5：消费者迁移 | 卡片经检索服务读取；时间线、来源回看、真实波形和处理状态；旧历史显式导入；淘汰客户端计费判断 | 旧接口与卡片兼容；导入幂等、保留时间及来源缺失标记；停止／失败时 UI 与真实资源一致 |
| PR 6：桌面闭环 | 建议先做 macOS PoC，再完成一种桌面系统；本地采集、处理、存储、检索；暂停、范围设置、休眠与设备变化处理 | 一段完整工作会话验证资源占用、存储增长、恢复与退出状态；明确测试设备、系统版本和采集音源；macOS 是实施建议，不是已验证结果或用户指定要求 |
| PR 7：网页云端节点 | 网页录音可靠上传、云端存储适配、鉴权、任务处理和同一检索契约 | 多用户数据隔离、续传、云端重启恢复、处理与保留策略验证；当前内存服务器不能直接视为已完成云端节点 |
| PR 8：移动端与跨端 | 移动本地录音、分享／截图导入，分别验证 Android 与 iOS 采集能力；之后选择性同步或联合查询 | 各平台能力矩阵、锁屏／中断验证、离线覆盖、跨端去重及删除传播可核对；不承诺无人操作自动开启 iOS 录屏 |

PR 1 后可以并行进行桌面原生采集和移动屏幕广播的最小 PoC，用于发现权限、耗电和后台生命周期限制。PoC 采用同一输入契约，隔离实验数据；它不替代持久化、处理和检索验收。

## 2. 阶段性可用结果

**M1：可靠记录（PR 1–3）。** 采集停止、处理失败或应用重启后，已保存的资料仍存在，能够解释每段时间有哪些记录和缺口。

**M2：Agent 可查（PR 4–5）。** 一个独立客户端使用公开工具找到历史资料，能定位原始证据；AI-ME 可以作为验收客户端，但安装和运行服务不依赖 AI-ME 或 Weora。

**M3：桌面日常使用（PR 6）。** 完成一种桌面系统的长期采集验证，能检查来源、暂停、搜索和删除，公布实测资源与存储情况。持续时间由验收场景确定，不将短时演示写成全天稳定。

**M4：多端节点（PR 7–8）。** 网页云端、桌面和手机共享契约，各自报告能力与可用性。同步和联合查询属于新增交付，不能仅凭多个节点都存在就宣称已经打通。

## 3. 检索质量评估

建立固定、可重复的小型语料与问题集，使用合成或明确授权的资料。至少覆盖以下五类，每类记录期望命中证据、允许的上下文和不能推出的结论：

| 样例 | 验收重点 |
|---|---|
| “昨天重试方案最后怎么定的？” | 找到最终决定及其前后文，区分早先提议和后续修正 |
| “上午看到的那份资料在哪？” | 找到来源与截图／页面文字，可实际打开证据 |
| 同一画面连续出现、多端重复导入 | 检索结果不被重复内容占满，原始来源仍可追踪 |
| 手机离线、转写积压、采集有缺口 | 返回真实覆盖范围，不能回答成“所有记录中都没有” |
| 引用来源被删除、访问范围缩小 | 所有读取入口和缓存均不泄露已不可访问内容 |

先建立至少 30 个具有标准证据的问题，拟定目标为至少 80% 的问题在 Top 5 结果中找到标准证据；这是待测产品目标，并非当前准确率。评估记录证据召回率、引用能否解析、回答有无证据支持，并记录端到端延迟、处理积压和每小时存储量。首次测量建立基线，再为明确的设备与语料设资源和性能预算。

确定性门槛优先：约定故障用例中已确认素材零丢失、重复写入不增加事实条数、删除和越权用例零泄露。随机生成的截图、规则卡片或模拟转写只能验证相应演示路径，不能证明真实采集质量。

## 4. 发布与回退

先使用隔离数据验证，再小范围启用新路径。每次上线记录应用版本、Schema 版本、处理器版本和启用的能力；停止新功能不得停掉既有资料的安全读取。回退遵循 [refactoring.md](refactoring.md) 的数据扩展原则，禁止通过删库或降级覆盖真实数据恢复旧代码。

每个阶段结束更新 [current-state.md](current-state.md)，分别标记已实现、已验证、已知限制与下一步。没有证据的项目保持待实施。

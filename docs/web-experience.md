# Daymark 网页体验与界面规范

**状态：前端设计与改造范围，2026-09-26。** 本文描述网页宣传站与网页工作台的页面结构。标注“待接入”的能力尚未实现；界面不得把演示内容当作用户历史。

## 站点结构

| 入口 | 页面 | 职责 |
| --- | --- | --- |
| `daymark.<域名>` | 宣传首页 | 说明个人上下文产品方向、三端定位和当前可体验范围，引导进入工作台 |
| `space.daymark.<域名>` | 录音 | 用户主动开启或停止网页麦克风，查看连接与实时转写状态 |
| `space.daymark.<域名>` | AI 聊天 | 用户向 Agent 提问；目标能力是通过上下文工具检索历史，并给出来源、时间和证据 |
| `space.daymark.<域名>` | 设置 | 查看麦克风、保存、处理和 Agent 查询能力的实际状态与范围 |

本地开发用 `/` 预览宣传首页、`/space` 预览工作台。工作台只有录音、AI 聊天、设置三个一级页面。不再把旧“课堂／会议恢复卡”、历史卡片、兑换码或手动文字资料库作为新版工作台入口。

## 页面行为

### 录音

空闲状态说明麦克风只在用户点击后启用。点击开始后依次显示连接中、授权中、录音中；停止后释放麦克风和连接。实时转写区只展示当前连接收到的文字。服务端返回 `mock_mode` 时明确显示“预置文本演示”，不能写成真实语音转写。

当前 `/ws` 后端仅支持短期内存会话，断开后删除会话，没有可靠分片确认和原始录音持久化。因此界面不得显示“已保存”“已上传”或把本次录音放入历史库。开始失败、权限被拒、连接中断应显示明确错误。可靠保存和处理进度在后续接入新采集协议后再出现。

### AI 聊天

主区域使用简洁的对话布局：标题、对话列表、输入区。Agent 的目标链路是 `context.search` 找候选、`context.get_event` 展开上下文、`context.get_source` 打开原始证据、`context.get_coverage` 说明搜索范围。答案要带来源和时间；找不到、未处理、设备离线是不同状态。

当前仓库尚无这些历史检索接口，也没有新 Agent 对话接口。前端先完成空状态、输入区、连接状态和结果容器的视觉结构；在接口接入前不发送请求、不生成假回答，输入操作保持禁用并说明原因。旧 `/api/ask` 只问当前短期会话，不充当历史检索接口。

### 设置

只展示已真实生效的状态。网页麦克风由录音页主动开启，站点当前没有持久录音、账户同步、Agent 授权管理；这些项目以“待接入”显示。不提供无效开关。今后存储位置、处理位置和 Agent 可查范围应独立配置。

## 视觉与组件

全站使用同一套色阶：深绿 `#1E533C`、浅绿 `#A4C8AE`、淡绿 `#EAF3E9`、近黑 `#17201A`、纸白 `#F7F8F3`。颜色在全局 CSS 令牌定义，Tailwind 语义色映射同一令牌。英语标题和品牌使用 Newsreader，中文正文使用 Noto Sans SC 并保留系统字体回退。

共用品牌标识、按钮、状态标签、页面标题与内容块。界面采用扁平色块和轻阴影，避免装饰描边与多层卡片。桌面使用侧边导航，窄屏使用底部导航；三个页面共用相同布局。可交互元素有清晰焦点态，状态信息不能只靠颜色表达。页面文案简短，当前能力和未来方向分别标注。

## 接入顺序

1. 完成三页前端和统一令牌，移除旧工作台入口。
2. 保留旧 `/ws`、`/api/recover`、`/api/ask` 服务端接口供兼容迁移；录音页仅复用 `/ws` 的真实连接状态。
3. 建设可靠采集与保存后，录音页增加上传确认和处理状态。
4. 建设上下文检索与 Agent 对话接口后，启用聊天输入和带证据回答。

前端构建通过只证明页面可编译。录音保存、历史检索、Agent 工具调用必须另行按真实服务验证，不能因页面已画出而标记为交付。

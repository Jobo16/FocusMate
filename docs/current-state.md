# 当前实现与目标能力对照

**更新日期：** 2026-09-26。基线为 Jobo16/FocusMate 提交 `a263a6b165816bccdb3385c31ccf4e98a92d1d20`；以下“当前”指本地 Daymark 前端改造后的工作树。已完成前端构建与页面查看，未验证真实麦克风、模型调用、持久化或真机。

## 当前可见产品

- 主域名角色：Daymark 宣传首页，说明产品方向、三端计划和当前预览边界。
- `space.` 子域名角色：只有录音、AI 聊天、设置三个一级页面。本地对应 `/` 与 `/space`。
- 录音页复用旧 `/ws` 连接：等待 WebSocket 打开后再请求麦克风与发送开始消息；错误时不假装正在录音；停止或离开页面释放连接与麦克风。转写仅在本次页面预览。服务端缺少 DashScope Key 时返回预置文字，页面会标注“预置文本演示”。
- AI 聊天页是待接入的前端结构。没有历史检索服务或 Agent 对话接口，输入停用，也不会生成演示答案。
- 设置页只呈现真实能力状态，没有尚未生效的存储或权限开关。
- 界面统一使用 [网页体验规范](web-experience.md) 中的颜色令牌、字体、按钮、状态和响应式布局。

## 仍需注意的边界

1. 旧服务端 `SessionStore` 是进程内 Map；WebSocket 断开后删除 session，任何转写都不能描述为“历史已保存”。
2. 旧 `/api/ask` 只基于当前短期会话，不是历史检索工具；新聊天页未调用它。
3. 旧浏览器历史与额度 localStorage 数据仍留在用户浏览器中，界面不读取，也没有自动迁移或删除。不能把旧卡片冒充含原始音频的资料。
4. 当前前端构建和页面导航检查不证明真实麦克风、上传、ASR、检索、权限与模型效果；这些能力需要按路线图单独验证。
5. 仓库 Dockerfile 及当前部署脚本尚未配置主域名与 `space.` 子域名的正式托管。前端根据 host 呈现不同页面；DNS、TLS 和工作台 `/ws` 反向代理另行部署。

旧源码基线的事实与目标契约见 [产品方向](product-direction.md)、[接口规范](api.md) 和 [重构路线](roadmap.md)。

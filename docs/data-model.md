# 数据模型与证据规范

> 状态：目标数据契约，尚未在基线代码中实现。本文定义领域语义；HTTP/MCP 的请求与响应以 [API 规范](api.md) 为准。新增字段使用 `snake_case`，旧 camelCase 契约只在迁移适配器边界转换。

## 1. 基本原则

原始素材、采集记录、提取结果、事件、推断和索引具有不同生命周期。它们必须独立标识并通过可追踪关系连接，不能全部塞进一个“记忆文本”字段。每条内容都要能回答：来自哪里、何时采集、经过什么处理、证据是否还在、谁有权读取。

时间统一使用带毫秒的 UTC ISO 8601，例如 `2026-09-26T05:00:00.000Z`；这是格式示例，不是实际记录。界面展示时再转换为用户时区。音频定位偏移使用整数毫秒，不能与绝对时间戳混用。

## 2. 稳定身份与所有权

所有 ID 使用客户端或服务端可安全生成的全局唯一、不透明字符串，不承载用户名、路径或授权信息，也不依赖 ID 的排序推断时间。

| 字段/实体 | 含义与不变量 |
| --- | --- |
| `owner_id` | 数据所有者。接入时由认证上下文确定并校验设备归属，不信任客户端自报值 |
| `node_id` | 当前存储、处理或检索节点；副本状态、路径和接收进度属于节点 |
| `origin_node_id` | 逻辑记录首次创建的节点，同步后保持不变 |
| `session_id` | 一次用户开启的采集会话，可横跨多次连接；不使用 WebSocket 连接 ID 代替 |
| `record_id` | 一条逻辑采集记录，例如一个完成封装的音频段或一次画面采样；重传与同步保持 ID |
| `asset_id` | 不可变素材的逻辑 ID，包括音频、图片或文本文件；文件改写产生新素材 |
| `event_id` | 一组有关联的记录与证据所组成的事件；成员和摘要通过事件修订维护 |
| `evidence_id` | 一个不可变版本的可定位证据；校正文本产生新 ID，并记录替代关系 |
| `processing_run_id` | 一次具体处理执行，用于追踪模型、配置、输入与输出版本 |

ID 不是访问凭证。所有按 ID 的读取必须重新校验所有者、来源限制与当前删除状态。

同一截图被多次采样时，可以在所有者与相同保留策略范围内对素材做哈希去重；每次观察仍保留独立 `record_id` 和时间。去重不能抹掉“再次出现”这一事实。避免跨用户去重接口泄露某个内容是否已存在。资产共享引用时，删除某条记录应撤销其引用，不能破坏仍被合法记录引用的素材。

## 3. 核心实体

### 3.1 设备、会话与记录

设备记录描述平台、采集器版本及可用能力。采集会话保存用户实际开启的来源、策略快照、开始/结束时间和状态；麦克风、系统播放音频与屏幕画面是不同来源，分别报告状态。

一条采集记录至少包括：

| 类别 | 关键字段或语义 |
| --- | --- |
| 身份 | `record_id`、`owner_id`、`origin_node_id`、`session_id`、设备标识 |
| 类型 | `source_kind`、原始来源描述、关联的 `asset_id` 列表 |
| 时间 | `recorded_at`、`recorded_end_at`、节点的 `received_at` |
| 顺序 | `device_seq`、`clock_epoch_id`、可用时保存单调时钟时间 |
| 校时 | `clock_offset_ms`、`clock_uncertainty_ms`、校时依据或缺失标记 |
| 来源上下文 | 可获得时保存应用、窗口、URL、页面标题；未知项保持空值 |
| 完整性 | 内容哈希、大小、格式、分片清单和完整性校验结果 |
| 管理 | 策略版本、逻辑修订、删除标记、派生处理状态 |

`recorded_at` 是设备在采集时报告的时间；`received_at` 是当前节点接收记录的时间。离线补传必须保留前者，不能把上传时间当作发生时间。每个副本保存自己的 `received_at`。

`clock_offset_ms` 的符号约定为“校准 UTC = 设备报告 UTC + 偏移”。设备重启或时钟基准变化时更新 `clock_epoch_id`，单调时钟和 `device_seq` 只在相应范围内比较。校时结果保留依据与不确定范围；新校准结果作为时间对齐修订记录，不覆写原始报告时间。跨设备时间只作为事件关联线索，不能强行排列本来无法确定先后的内容。

录音的传输小包可以合并为一个可独立校验的逻辑音频段。传输包编号用于补传，`record_id` 用于持久记录；两者不能混为一谈。段长度是可调采集策略，需要兼顾掉电恢复、上传开销与处理吞吐。

### 3.2 原始素材与节点副本

`assets` 保存素材身份、校验值、媒体类型、长度及音频/图像必要参数。`asset_replicas` 保存 `(asset_id, node_id)` 对应的存储地址、大小校验、可用状态与保留期限。外部 API 不直接暴露本地绝对路径或对象存储内部凭证。

音频保存采样率、声道、编码与时长。用于 ASR 的重采样版本是派生素材，并保留相对于原始音频的时间映射。图片保存原始尺寸；裁剪、缩放或旋转产生的 OCR 输入必须保留到原图的坐标变换。

### 3.3 提取结果与证据

文本提取不能脱离来源独立存在。每个 `evidence_id` 应包含关联记录、素材、提取文本、生成该版本的处理执行及可定位范围。

| 证据来源 | 最小定位信息 | 处理要求 |
| --- | --- | --- |
| 语音转写 | `asset_id`、`start_ms`、`end_ms` | 偏移相对原始素材；若从处理版本提取，应转换回原始位置 |
| 截图 OCR | `asset_id`、原图坐标范围 | `bbox` 采用相对原图宽高的 0–1 归一化坐标；保留原图尺寸 |
| 导入文字 | `asset_id`、字符范围或稳定块 ID | 字符单位与编码约定固定；重新归一化后发布新证据版本 |

ASR 的 partial 结果具有可撤回、可替换性质，按上游分段 ID 和修订号更新预览。默认长期索引只接收 final 段。若产品开放“查看处理中内容”，结果必须标注非最终，不能与稳定索引混为一体。

final 段也可能被人工校正或模型重处理。此时新增证据版本并通过 `supersedes_evidence_id` 连接旧版本；历史引用仍指向原证据，读取时说明已被替代。原始素材删除后不能把摘要冒充原始证据，应返回相应不可用原因。

### 3.4 事件、关联与推断

事件保存时间范围、标题、关联记录/证据、事件修订和状态。事件成员表记录关联方式、关联理由、置信度以及生成该关联的处理执行。时间相邻、窗口相同和语义接近可作为候选依据，不能直接证明“属于同一个任务”。用户确认的关联与模型建议的关联需要区分。

事件摘要、提取任务和实体属性使用统一的 `epistemic_type` 区分证据层级：

| 值 | 含义 | 示例 |
| --- | --- | --- |
| `observed` | 直接采集到的原始观察及元数据 | 某时刻记录了一张页面截图 |
| `extracted` | 对原始素材的转写或结构化提取 | 录音中出现“下周再评估”的文字；仍受 ASR 误差影响 |
| `inferred` | 模型概括、关联或推断 | 推测该讨论与某项目有关，或生成事件摘要 |

所有 `extracted`、`inferred` 内容都要保留支持它的 `evidence_id` 或派生依赖，不能仅记录一个置信度数字。识别到的人名是文本实体，不自动等同于已验证的真实联系人；出现某项观点不等于用户持有该观点；提出方案不等于作出决策。

事件调整成员后产生修订，受影响的摘要和索引标记为过期。拆分或合并事件应保留旧事件到新事件的重定向关系，避免已有引用悄悄指向不同含义。

## 4. 五类状态不能合并

| 状态轴 | 所属对象 | 枚举与语义 |
| --- | --- | --- |
| `capture_status` | 每个采集来源 | `idle`、`starting`、`capturing`、`paused`、`interrupted`、`stopped`、`error` |
| `processing_status` | 记录的聚合处理进度 | `pending`、`running`、`partial`、`ready`、`failed`、`cancelled` |
| `jobs.status` | 单个作业 | `queued`、`running`、`succeeded`、`failed`、`cancelled` |
| `index_status` | 各种派生索引 | `pending`、`building`、`ready`、`stale`、`failed` |
| `raw_status` | 某节点的素材副本 | `pending`、`available`、`missing`、`expired`、`deleted` |

`processing_status=ready` 表示当前策略要求的处理阶段已完成，不代表所有索引更新完成或原始素材永久可读。`partial` 表示已获得可用结果但部分要求尚未完成或失败，需要同时返回阶段详情。暂停采集不会取消已排队的合法处理；要停止处理必须单独取消作业或修改策略。

`raw_status=missing` 表示本应存在的副本缺失或校验失败；`expired` 表示按保留策略过期；`deleted` 表示明确删除。节点离线通过 `coverage` 表达，不能伪装成素材缺失。无权访问是授权结果，不作为素材状态写回数据库。

## 5. 作业、版本与可重建索引

作业保存输入 ID 与版本、阶段、幂等键、尝试次数、下一次执行时间、租约、错误类别和处理执行。worker 崩溃后租约到期可重新领取；输出使用幂等提交，避免重复证据与重复事件成员。

每次执行至少记录：`pipeline_version`、处理器名称/版本、提供方与模型标识、可取得的模型版本、提示词版本、配置摘要、代码版本、输入版本及输出 ID。提供方不能提供精确模型版本时如实记为未知，同时保留调用日期与请求配置，不能声称完全可复现。

`derivation_edges` 跟踪记录→提取→证据→事件摘要→索引的依赖。FTS、向量和摘要都是派生层；重建索引不应要求重新录音。向量记录保存嵌入模型、维度、归一化方式及索引版本，更换模型时不得混用不同空间的向量。

`index_watermark` 按节点和索引版本记录 `known_indexed_through` 与 `pending_ranges`，由真实的提交和作业进度推导。没有连续覆盖依据时 `known_indexed_through` 可以为空。迟到数据会生成新的待处理范围，不能因已有较晚记录就宣称此前完整。

## 6. 删除、保留与恢复

用户删除某条记录时，应先提交删除标记，使检索与读取立即排除该记录，再异步清理素材引用、文本、事件成员、摘要、全文索引、向量和缓存。仍在执行的作业必须在发布前检查删除代次，防止删除后重新生成内容。事件仍包含其他资料时，需要重建其摘要并撤销已删除证据的引用。

`tombstones` 保存逻辑 ID、删除代次、来源节点、操作时间和待同步状态。离线节点重新上线时，先应用有效删除标记，再处理增量上传，旧副本不能复活记录。已实际删除的原始文件不能承诺恢复；恢复操作只适用于仍处于明确保留期的可恢复副本，并需要重新校验和发布新修订。

单独缩短原始素材保留期，可以按用户选择保留提取文本，但必须把 `raw_status` 更新为 `expired`，让 Agent 知道无法再核对原始音频或图片。完整删除则默认传播到所有派生内容。备份保留与删除处理需要明确策略；不得声称已经撤回外部 Agent 之前合法取得的副本。

## 7. 建议的逻辑表

第一版可以采用关系数据库实现，下列为逻辑对象，不要求每项独立数据库或服务：`devices`、`nodes`、`capture_sessions`、`records`、`assets`、`asset_replicas`、`extractions`、`evidence`、`events`、`event_members`、`processing_runs`、`jobs`、`outbox`、`derivation_edges`、`index_state`、`tombstones`。

本地与云端遵守相同身份及生命周期语义，不要求 SQLite 与 PostgreSQL 的物理表定义完全相同。外部契约由 `packages/shared` 统一维护，存储适配器负责映射；未来 Python worker 如被引入，应消费导出的版本化契约，避免手工维护第二套相互漂移的字段定义。

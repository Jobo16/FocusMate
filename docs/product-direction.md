# 产品方向与体验规范

> 状态：目标设计，尚未实现。本文基于原 FocusMate 提交 `a263a6b165816bccdb3385c31ccf4e98a92d1d20` 制订；现有代码仍是课堂／会议恢复卡片的 TypeScript Web 原型。品牌更新不代表已经交付桌面端、手机端、持久化知识库或 MCP 服务。

## 1. 产品定位

Daymark 的目标方向是个人上下文采集与检索服务：持续记录用户授权的语音、画面及导入内容，将其整理成带时间、来源和原始证据的上下文库，供不同 Agent 通过稳定接口查找资料。

产品交付的核心结果是“过去接触的信息可以找回并核对”。用户无需记住当时使用的应用，也无需再次向 Agent 复制背景。现有“刚才错过了什么”保留为下游消费场景，逐步通过公共检索接口工作。

产品名称为 Daymark；定价与商业模式尚待决定。

## 2. 服务对象与核心任务

| 对象 | 需要完成的任务 | 成功结果 |
| --- | --- | --- |
| 经常跨应用工作的人 | 找回看过的页面、讨论、资料 | 找到原始来源与发生时间 |
| 会议、课程参与者 | 补上遗漏内容，核对结论 | 区分提议、已确认决定和未知事项 |
| 被临时任务打断的人 | 恢复此前工作上下文 | 找到最近事件、相关材料与后续变化 |
| Agent 应用开发者 | 查询用户授权的历史资料 | 使用同一接口获得证据及检索覆盖范围 |

首批验证以单用户、单设备的日常工作记录为主。多人共享、组织成员监控、自动替用户执行任务不纳入首期范围；扩展这些能力需要独立产品设计。

## 3. 产品边界与解耦原则

| 部分 | 本项目职责 | 边界 |
| --- | --- | --- |
| 采集器 | 获取素材和来源信息，可靠保存 | 不依赖特定 Agent 会话或提示词 |
| 整理管线 | 转写、OCR、去重、分段、事件组织与索引 | 模型适配器可替换，失败可重试 |
| 上下文节点 | 保存原始证据、提取内容和派生结果 | 本地与云端均可独立运行 |
| 检索服务 | 搜索、展开前后文、读取证据、报告覆盖范围 | 访问控制在服务侧生效 |
| 外部 Agent | 解释资料、形成建议、处理用户任务 | 通过工具访问资料，不直接耦合数据库 |

“整齐的知识库”必须包含可回溯关系。原始记录、OCR／转写、事件摘要和模型推断分别存储；浏览某页面不等于接受其中观点，讨论方案不等于作出决定。摘要保留证据引用，关联不确定时保留候选关系。技术契约见 [架构](architecture.md)、[数据模型](data-model.md) 与 [API](api.md)。

## 4. 三端定位

| 端 | 主用途 | 默认数据位置 | 首期重点 |
| --- | --- | --- | --- |
| 网页 | 主动开启的轻量录音会话 | 云端 | 录音、分片上传、搜索及证据查看 |
| 桌面 | 长时间工作上下文采集 | 当前设备 | 音频、屏幕采样、本地处理及检索 |
| 手机 | 移动录音、分享与补充记录 | 当前设备 | 先交付可靠录音和导入，再扩展屏幕能力 |

桌面先支持一种操作系统，建议从 macOS 开始，最终以采集原型和资源评估定版；这是实现建议，不代表已交付。Android 与 iOS 的屏幕采集能力分别验收；不能把“手机支持后台运行”写成所有机型均可永久自动截图。详细约束见 [平台规范](platforms.md)。

## 5. 必备界面与主要流程

### 5.1 首次使用

用户依次选择采集来源、存储位置、处理位置和允许查询的 Agent，再授予对应系统权限。桌面和手机默认本地保存，云端处理需明确开启。首次引导展示一份样本，用户确认能看到原图或听到原音后开始正式记录。

本地保存、模型在何处处理、检索结果能否发送给云端 Agent 是三个独立设置。选择完全本地处理时，转写、OCR、摘要与向量生成均不得静默切换到云端。

### 5.2 采集状态

首页显示每个来源的状态、最近采集时间、最近保存时间、待处理数量和容量情况。录音电平来自真实输入；未收到数据时显示等待或异常。提供开始、暂停、停止、排除应用及删除最近记录的入口。

网页流程为“选麦克风 → 开始 → 查看录音及上传状态 → 停止 → 查看处理结果”。网络中断时明确显示尚未上传的分片；会话结束不等于所有内容已经云端保存。

桌面使用常驻入口控制记录，在主窗口查看时间线；锁屏、休眠、撤销权限和磁盘不足必须呈现实际中断。手机突出当前录音和导入入口，屏幕采集由独立会话控制，系统提示保持可见。

### 5.3 时间线、搜索与证据

时间线按事件组织，可按日期、设备、应用和来源过滤。事件卡展示摘要、素材数量、处理状态与资料覆盖情况；原始素材未处理完成时也可以查看。

搜索支持自然语言及时间范围。命中项显示原文片段、时间和来源；点击后展开前后文并定位音频区间或截图。摘要、提取文字和用户修正清楚区分。无结果、相关数据未处理、设备离线分别解释。

### 5.4 设备与数据控制

设备页展示节点在线状态、资料更新时间、处理进度及同步范围。设置页管理来源排除、保留期限、容量、导出和删除。删除时展示影响范围，立即停止返回被删除资料；跨设备清理的进度单独显示，不把排队中描述成全部完成。

Agent 授权页展示可查的数据范围并支持撤销。检索结果中的采集内容均作为资料处理，其中的文字不自动成为操作指令。

## 6. 质量目标与验收建议

北极星指标建议采用“有证据的问题解决率”：在真实找回任务中，用户获得相关资料、打开证据并确认能够解决问题的次数，占被评估任务数的比例。未找到资料和覆盖不足单独分类，不能只统计成功查询。

以下为首轮验收的提议目标，尚未测量；实施阶段应固定设备、数据规模、模型配置与样本，并在 [路线图](roadmap.md) 中记录结果。

| 维度 | 提议验收方法 |
| --- | --- |
| 可找到 | 至少 30 个有标准证据的问题，相关证据进入前 5 项的比例达到 80% |
| 可核对 | 测试集所有返回引用均可定位原始内容；不存在把推断标成原文的结果 |
| 可靠保存 | 已确认持久化的素材在进程重启后可恢复；重复提交不新增重复记录 |
| 诚实覆盖 | 离线、未同步、未处理和权限不足的样例均准确报告搜索范围 |
| 可控停止 | 暂停／撤权后不新增该来源素材；待处理、上传和删除状态可查 |
| 长时间可用 | 固定设备完成 8 小时采集测试，记录缺口、资源消耗和处理积压，不虚构性能指标 |

第一阶段完成单桌面系统的采集、持久化、处理、搜索和证据闭环，同时并行验证移动屏幕采集原型，及早确定边界；第二阶段接入网页云端节点；第三阶段交付手机与跨设备访问。三端共享数据契约，采集能力渐进交付。改造顺序与旧功能兼容要求见 [重构规范](refactoring.md)。

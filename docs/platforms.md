# 多端采集与能力规范

> 状态：目标规范，尚未实现。适用于 FocusMate 后续采集器设计；现有 Web 原型不代表原生端能力。平台资料于 2026-09-26 核对，正式开发时须按目标系统版本再次验证。

## 1. 共同原则

“无感采集”在本项目中指用户授权并开启后低打扰运行，保留系统采集提示和明确停止入口。周期采样仅在有效采集会话内运行；定时器不能替代系统权限或重新启动已失效的会话。

来源至少区分麦克风音频、系统播放音频、屏幕画面、用户导入内容。某个来源可用，不代表其他来源也可用。采集器写入统一素材结构，后续转写、OCR 和索引异步处理，避免模型故障阻塞记录。

## 2. 平台能力与交付范围

| 平台 | 首期交付目标 | 后续能力 | 默认保存位置 |
| --- | --- | --- | --- |
| Web | 用户主动录音、分片上传 | 用户选择的屏幕共享、内容导入 | 云端；未上传分片仅作临时缓冲 |
| 桌面 | 单一操作系统上的持续音频与屏幕采样 | 其他系统、结构化应用内容 | 本地 |
| Android | 用户开启录音、分享导入 | 授权屏幕会话中的周期采样 | 本地 |
| iOS | 用户开启录音、分享／截图导入 | ReplayKit 广播原型通过后再承诺 | 本地 |

桌面建议先实现 macOS，其他系统后续交付；手机屏幕原型与桌面首期并行验证。跨平台 UI 和语言仅是候选实现选择。原生采集需要单独适配，不能以某 UI 框架支持多端作为采集能力已经一致的依据。

### Web

麦克风采集使用安全上下文中的媒体接口并取得授权；权限、设备丢失与轨道结束必须反映到界面。[W3C 媒体采集规范](https://www.w3.org/TR/mediacapture-streams/)

屏幕采集需要用户操作触发并选择共享对象，授权不能持久保存后自动复用。后台页面调度和关闭行为不适合作为全天采集承诺；网页按主动会话验收。[W3C 屏幕采集规范](https://www.w3.org/TR/screen-capture/)

分片具有稳定标识和序号，收到服务端持久化确认后才显示已上传。断网保留可用缓冲并显示容量；页面关闭可能留下未上传内容，UI 必须提前说明。缓冲上限、浏览器存储回收与恢复策略须在实现时验证。

### 桌面

macOS 可评估 ScreenCaptureKit；Windows 可评估 Windows.Graphics.Capture，其接口提供显示器或窗口的画面获取能力。各平台需要分别处理权限、选区和采集终止事件。[Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)、[Microsoft 屏幕采集文档](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)

屏幕先做变化检测与定时兜底采样，保存可核对的帧及时间。建议把多屏、窗口切换、缩放和受保护内容列为原型用例。无法获得页面 URL 时保持未知，不通过窗口标题伪造 URL。

麦克风与系统声音分别选择设备和处理路由变化。Windows 系统声音可研究 WASAPI loopback；这种能力不等于任意应用音频都保证可捕获。[Microsoft loopback 文档](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

桌面首期默认锁屏暂停屏幕采集；录音按用户设置和系统实际能力处理。休眠或进程退出形成明确的记录缺口。自动启动只恢复已选择的策略，不能绕过已撤销的权限。

### Android

MediaProjection 按会话取得用户同意，授权令牌不可跨新会话任意复用。有效会话内部可持续接收画面并采样，无需每张截图重新确认。Android 15 QPR1 及以上锁屏会自动停止屏幕投影；收到停止回调后清理资源并更新状态。[Android MediaProjection](https://developer.android.com/media/grow/media-projection)

录音和投影须声明相应前台服务类型、权限并遵守启动限制。麦克风的“使用期间”权限限制，意味着不能假定应用在任意后台时刻都能重新启动录音。[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)

系统播放音频捕获另受来源应用的捕获策略等条件限制，不能以麦克风授权代替。[Android 音视频捕获](https://developer.android.com/media/platform/av-capture)

验收覆盖前后台切换、锁屏、系统停止、电话打断、低电量和进程回收。会话失效后显示“需要重新开启”，禁止继续显示正在截图。

### iOS

用户开启的录音需要配置音频会话与后台音频模式，并处理打断及路由变化；不得将具备后台模式解释为永久不断录音。[Apple 音频应用指南](https://developer.apple.com/library/archive/documentation/Audio/Conceptual/AudioSessionProgrammingGuide/AudioGuidelinesByAppType/AudioGuidelinesByAppType.html)

跨 App 画面采集研究 ReplayKit 系统广播及扩展。Apple 技术支持明确没有无需用户介入、从后台自行启动广播的机制；关于后台持续 OCR 的可靠性，官方建议先做原型。[Apple 后台启动答复](https://developer.apple.com/forums/thread/839450)、[Apple 持续 OCR 答复](https://developer.apple.com/forums/thread/818940)

因此首期提供录音与用户主动导入。广播会话的持续性、资源限制、系统打断及分发要求都需另行验证，文档与 UI 不宣称“全天自动跨 App 截图”或保证通过应用商店审核。

## 3. 状态必须按来源分别报告

以下为状态语义；实际字段和枚举以 [数据模型](data-model.md) 为唯一契约，接口映射见 [API](api.md)。

| 维度 | 必须表达的情况 | UI 行为 |
| --- | --- | --- |
| 能力 | 支持、受限、尚未验证、不支持 | 解释当前设备可开启哪些来源 |
| 权限 | 未请求、请求中、已授权、拒绝／撤销 | 提供与实际平台一致的下一步 |
| 采集 | 空闲、启动中、采集中、暂停、中断、已停止、错误 | 只有实际收到数据才显示正常采集 |
| 保存 | 最近持久化时间、待保存数量、失败原因 | 已采集与已保存分别显示 |
| 处理 | 排队、处理中、完成、失败、取消 | 允许查看原始素材和重试 |

每个来源同时报告最近收到数据时间与原因；整体状态可显示部分可用。例如屏幕中断而麦克风继续录音时，应准确展示两者，不能用一个绿色图标代表全部正常。

## 4. 本地、云端与缺口处理

所有端分别配置存储位置、处理位置和 Agent 可访问范围。完全本地模式禁用云端转写、OCR、向量生成及摘要适配器；切换处理策略对所有尚未发送的数据立即生效，已排队任务执行前重新校验，已有资料迁移需单独显示进度。

本地节点离线且数据未同步时，云端 Agent 无法搜索该节点。检索必须报告实际覆盖范围、更新进度和遗漏节点，禁止把局部结果描述成用户全部历史。相关协议见 [架构](architecture.md) 和 [数据模型](data-model.md)。

容量不足时优先停止新增素材并说明原因，禁止静默覆盖仍在保留期内的证据。排除规则在素材持久化及远程发送前执行；受平台信息不足影响而无法落实某条规则时，应说明限制并采用可保证的采集范围。

平台适配器交付前必须验证撤权、暂停、重启和重复上传，证明状态真实、已确认保存的数据可恢复、缺口可见。各阶段门槛见 [路线图](roadmap.md)，代码迁移要求见 [重构规范](refactoring.md)。

## 背景与用户确认的范围

原型围绕课堂／会议中的短时间上下文恢复。新的目标是持续收集用户授权的外界信息，包括语音、截图和其他输入，并整理为 Agent 可通过工具检索的个人资料库。

已确认的产品要求：

1. 数据收集与 Agent 使用解耦。
2. 网页端轻量使用，以录音为主，保存到云端。
3. 桌面与手机 App 支持各平台实际允许的持续采集，以本地保存为基础。
4. 核心工作是将原始素材转成整齐、可检索、可回溯的资料。
5. 三端使用一致的数据模型和检索契约，而非强行拥有相同采集能力。

## 本次采用的设计

- 拆分采集器、整理管线、上下文节点、检索服务及消费端。
- 保存原始证据、提取结果、事件及派生索引，分别管理版本和保留期限。
- 查询返回时间、来源、证据和覆盖范围。
- 本地存储、处理位置、同步策略、Agent 访问范围分别配置。
- 首先完成一个桌面系统上的核心闭环；网页云端复用契约，手机平台 PoC 可提前并行。
- 当前 TS 代码增量重构；Python worker 是可选适配方向，暂不进行整仓语言迁移。
- FocusMate 恢复卡作为参考消费端，AI-ME 等作为外部接入案例，核心不得导入其运行时或私有业务模型。

## 关键取舍

| 采用 | 原因 | 代价 |
| --- | --- | --- |
| 证据优先、摘要可重建 | 支持核对、修正与模型更换 | 需要素材和派生依赖管理 |
| 各节点独立持久化 | 满足本地优先和离线采集 | 联合查询必须报告覆盖缺口 |
| Agent 通过工具查询 | 多消费者复用，内部存储可演进 | 需要稳定 API、权限与预算控制 |
| 按平台实现采集 | 产品承诺符合公开能力 | 手机不能复制桌面的全部体验 |
| 增量兼容迁移 | 保留可运行原型与可回退路径 | 一段时间内新旧协议共存 |

## 待验证而非被假定成立

iOS 持续系统广播的可靠性；手机耗电与后台生命周期；中文 OCR／ASR 和检索效果；目标设备上本地模型的资源占用；跨设备事件关联质量；真实用户的长期记录价值。

正式商业模式、品牌更名、完整团队协作权限、全平台发布日期和无限保留均未确定，不应出现在功能承诺里。
